How the measurement works

Three different claims, three different methods. The census counts what happened. The rules are proved. Only the third claim needs an experiment.

By Ramon Gonzalez · Created 2026-08-15 16:23 ET · Last updated 2026-09-03 10:00 ETContent 2026-08-17 01:24 ET · Style 2026-09-03 10:00 ET · Organization 2026-09-03 10:00 ET

Three claims, kept separate

Most of the argument does not depend on the experiment at all, and it is worth being clear about which part depends on what.

  • Models almost never decline. A count over published responses. No model was called, nothing was sampled, and anyone can recount it from the same public archive.
  • A rule that prices being wrong would elicit an honest probability. Mathematics, checked numerically. It is true whether or not any model responds to it.
  • Announcing the rule changes what a model does. The only claim that needs an experiment, and the only one that could turn out false.

The pipeline

Each stage does one thing and hands a stable artefact to the next, so a failure in one place cannot quietly contaminate another.

  1. Frozen item slices. Questions are sampled round-robin across strata with a deterministic hash order, then written to disk. The same run tomorrow asks the same questions, so a difference between two runs is a difference in behaviour rather than in sampling.
  2. Contracts. A contract is the scoring rule as the model is told it. The identical question goes out under every contract, including a control that announces nothing. The contract is the only thing that varies.
  3. Generation. Resumable, cached, concurrency-limited, and capped by a hard spend limit. Results are matched back to their prompts by an index carried through the await, because completions arrive out of order and zipping them to the submission list would silently mismatch answers to questions.
  4. Grading. Deterministic wherever the benchmark allows it. An LM judge is used only for free-form answers, and is itself validated against hand labels before its verdicts are trusted.
  5. Scoring. Applied afterwards, in SQL, over stored raw responses.

Why scoring happens last

The announced contract varies at generation time, because that is the experiment. Everything downstream, the penalty arithmetic, the calibration decomposition, the abstention gates, runs afterwards over stored responses. Baking a scoring parameter into the runner would mean re-calling every model to ask what a different penalty would have produced. Applying it afterwards means the whole parameter sweep is free, and the stored responses stay a fixed record that later analysis cannot alter.

Four rules that must not be broken

Each of these exists because breaking it produces tables that look completely plausible and are wrong in the direction of the hypothesis.

Unparseable output is incorrect, never an abstention

A response that ignored the format did not decline to answer. Grading it as silence makes incoherence free. On published runs of one benchmark, that single mistake lets a 18.7%-accuracy small model outscore a 51.5%-accuracy large one.

Every multiple-choice item gets an explicit “I don't know” option

Without one, a rule that prices error is just a positive affine transform of accuracy, so it cannot change the ranking no matter how steep the penalty. Verified numerically across 69 published runs: maximum deviation 1.2e-15. Remove the option and the experiment becomes incapable of detecting its own effect.

Verdict parsing tests "incorrect" before "correct"

The word INCORRECT contains the word CORRECT. A substring match in the wrong order graded every wrong answer as right, and the resulting tables looked entirely reasonable.

Reasoning-truncated output is flagged, not graded

A model that spent its whole budget thinking returns empty content. That is a truncation, not a refusal, and counting it as silence would manufacture exactly the finding the experiment is looking for.

What is checked automatically

The properness of every scoring rule is verified numerically over the whole probability grid. The full pipeline runs end to end against a mock endpoint on every commit, with no API key and no spend, and asserts the direction of the result: contracts that price error more steeply must produce more abstention and fewer errors. That check has already caught two bugs that would have inverted the experiment while producing plausible output.

Zero runtime dependencies The tooling installs nothing. The runner uses the standard library, storage is SQLite, and every metric is a SQL query you can read. When the argument is that scoring should be inspectable, the tooling should not need a lockfile to inspect.

Glossary

Every term of art this site uses, in one place. Terms are defined in passing where a page first uses them, with a dotted underline you can hover or tab to. This is the canonical version, and where the two ever disagree, this one is wrong and should be fixed.

Accuracy-only tuning
The control arm of the fine-tuning comparison, and the conventional way reinforcement learning is applied to questions with verifiable answers. Reward is 1 if the answer is correct and 0 otherwise, which mirrors the usual benchmark objective. The model is still asked for a probability, and that number has no effect on the reward. It is not the default form of all fine-tuning. The fine-tuning page says this at length.
Arm
One condition in an experiment, with everything else held identical, so a difference between two arms is caused by the thing that differs between them. There are three kinds here: contract arms vary what the prompt announces, reward arms vary what the training rewards, and evaluation arms vary what the scoring prompt says at test time.
AUROC
Area under the ROC curve. For a stated probability, the chance that a randomly chosen correct answer carried a higher probability than a randomly chosen wrong one. 0.5 is a coin flip, 1.0 is perfect separation. It measures whether the numbers rank right answers above wrong ones, and says nothing about whether the numbers are the right size.
Break-even, √c
Under the quadratic rule with an assertion cost c, answering beats staying silent exactly when the probability of being right exceeds √c. At c = 0.09 that is 30%. Under ordinary accuracy grading c is already set, to zero, so the break-even is zero and there is never a reason to decline.
Brier score
The mean squared error of a stated probability, averaging (p − outcome)². Lower is better. The quadratic score used here equals accuracy minus Brier loss, which is why a model can lose accuracy and still gain score.
Calibration
Whether stated probabilities are the right size. A calibrated model that says 70% is right about 70% of the time. Distinct from accuracy, which is how often it is right, and from resolution, below.
Census
The count underneath the whole project: every per-question model output in the public EvalEval “Every Eval Ever” datastore, searched for any of roughly eighteen ways of declining to answer, across the entire generation including reasoning traces. 1,089,024 responses, 104 models, 36 benchmarks.
Checkpoint
A saved set of model weights. Here it means the unchanged base model plus one arm's LoRA adapter. Four exist: one per reward arm, and the untouched base as a comparison.
Contract
The scoring rule as the model is told it, in the system prompt. The contract is the intervention: the identical question goes out under every one of them, and nothing else varies.
Contract arms, the eight
control announces nothing, which is what nearly every benchmark does today. guess announces binary grading out loud, that a wrong answer costs nothing more than no answer. thresh75 is the published threshold proposal: answer only above 75% confidence, wrong answers cost 3. quad_formula gives the quadratic rule as algebra only. quad_plain gives its implication in plain English with no algebra. quad_both gives both, and is the intended default. quad_c50 is the same rule with speaking priced higher, so the break-even moves to 50%. deploy states an identical incentive as a deployer's operating instruction rather than as grading, and is the arm that can falsify the whole programme.
Coverage, and risk-coverage
Coverage is the fraction of questions a model answered rather than declining. A risk-coverage curve plots error rate against coverage as the abstention threshold moves, which is how two models that decline different amounts can be compared at all.
Harness
The software that runs the experiment: it builds the prompts, calls the models, stores the raw responses, grades them, and computes the metrics. It is kept separate from the scoring so a scoring parameter can change without re-calling anything.
LM judge
A language model used to decide whether a free-form answer is correct, on OpenAI's SimpleQA rubric, where no deterministic check is possible. It is the one link in the pipeline that no test can cover, so it is validated against hand labels before its verdicts are used. Below 90% agreement the free-form results are unusable and only the deterministic benchmarks stand.
LoRA
Low-rank adaptation. A small set of extra weights trained alongside a frozen base model, cheap to train and cheap to store. When the fine-tuning results say the weights changed, it is the adapter that changed and not the base.
Miscalibration, and resolution
The two halves a proper score decomposes into, following Murphy (1973). Miscalibration is the part recoverable by rescaling the stated numbers alone, without changing a single answer. Resolution is how much those numbers genuinely separate right answers from wrong ones, and has to be earned. On published runs the first exceeds the second several times over.
NOT_ATTEMPTED, CORRECT, INCORRECT
The three grading verdicts. NOT_ATTEMPTED is an explicit abstention, and it is the primary outcome of the experiment. Unparseable output is graded INCORRECT and never NOT_ATTEMPTED: a response that ignored the format did not decline to answer, and grading it as silence would make incoherence free.
On-policy, and rollout
A rollout is one response the model samples during training. On-policy means it learns from its own current outputs rather than from a fixed file of someone else's, which is what lets a reward shape behaviour instead of teaching imitation.
Paired design
Every arm sees the identical frozen questions, so question difficulty cancels within a model and the comparison runs item by item rather than group against group. The test is McNemar's, over only the items whose outcome disagreed between the two arms.
Positive affine transform
Multiplying by a positive number and adding a constant. It changes the scale of a score without changing the order. This is the reason a penalty alone cannot reorder a leaderboard: with no explicit abstention option, the penalised score works out to (1+p)·accuracy − p, which is a positive affine map of accuracy. Verified across 69 published runs, maximum deviation 1.2e-15. The appended “I DON'T KNOW” option is what breaks the affinity, which is why it is not optional.
Reward arms, the three
Accuracy-only pays 1 for correct and 0 otherwise, ignoring the stated probability. Confidence-aware pays the quadratic rule, so the stated probability finally costs something. Confidence plus cost pays the quadratic rule and charges a flat 0.09 for asserting anything at all. One tuning method, three reward objectives, from one base model.
Strictly proper
A scoring rule under which reporting the probability you actually believe maximises your expected score, and any other report lowers it. Strictly means the honest report is the unique best one rather than merely tied with others.
Stratified frozen slice
The questions themselves, sampled round-robin across strata in a deterministic hash order and written to disk before any run. Frozen, so the same run tomorrow asks the same questions and a difference between runs is a difference in behaviour. Stratified, so no arm gets an easier draw.
