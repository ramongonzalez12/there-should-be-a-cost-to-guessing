Does the harness reproduce a published benchmark?

Before asking whether an announced scoring rule changes what a model does, the environment has to be able to reproduce a result somebody else already published. Six current models did. Three more are excluded, and three routes have only a one-item connection check.

The gate

Each model was given every GPQA Diamond question once, under the published zero-shot prompt, with the reasoning effort and temperature its published result used. A model passes only if the number it got right falls inside the range that published score implies at this sample size, and if its saved request configuration matches what was declared in advance.

The range is a central 95% binomial interval for a fresh run of this size at the published rate. It treats questions as independent trials of equal difficulty and does not carry the uncertainty in the published estimate itself, so it is a diagnostic rather than an exact coverage claim.

Why one pass is fully recorded and five are reconstructed

The runner stored each call's inference parameters, provider, returned model identifier, reasoning-token counts, item identifiers, and the question and answer-key snapshot it was graded against. The five earlier passing runs did not store the full message body. Their prompts are rebuildable from frozen item identifiers, the dataset hash, and committed prompt code, but rebuilding evidence is weaker than recording it at inference time.

MiniMax M3 was run after the harness changed. Its 198 calls store the exact ordered messages and their hash, so it receives an unqualified PASS. The other five are labelled PASS_RECONSTRUCTED. The gate applies that distinction automatically, without looking at the scores first.

The three that did not count

These runs are kept visible because a gate is useful only if failures remain in the record. None is converted into a pass by dropping a missing response, loosening a routing rule, or selectively replacing hard items.

Claude Sonnet 5 (adaptive, max)

Six of 40 responses (15%) exhausted the 128,000-token output allowance without emitting an answer. That is above the pre-registered 5% format-failure threshold, so the arm is excluded rather than retried.

Muse Spark 1.2 (xhigh)

One of 198 calls ended in an ambiguous OpenRouter 502 network error. A second, explicitly authorized attempt produced the same error and no billed response. The missing pass@1 outcome makes the arm invalid, even though its penalized 88.9% falls inside the diagnostic interval.

DeepSeek V4 Pro 0813 (max)

The one connection check was rejected before inference by the account's existing OpenRouter data-policy routing restriction. No privacy setting was loosened, no alternate provider was substituted, and no inference was billed. The model was not pursued further.

Invalid is not the same as a performance miss Claude Sonnet's score and Muse Spark's penalized score both sit inside their diagnostic ranges. Sonnet still fails the 5% format ceiling, and Muse still lacks one pass@1 API outcome after two explicitly recorded attempts. The number alone cannot overrule the measurement protocol.

Connection checks are not replication evidence

Kimi K3, Qwen3.8, and Claude Haiku each received one item to verify that the published-style request could reach its first-party OpenRouter route. These checks establish plumbing only. They do not enter the six-model result.

What this does not establish

  • It is not an exact replication. The published figures average five repeats per model, 990 trials in all. This is one pass. The exact answer-choice permutation behind the published numbers is not disclosed, so the closest documented construction was used instead.
  • It is not a claim about the models. Nobody should read these as new capability estimates. The question is whether this harness lands where the published number says it should.
  • Each model was checked on its own. With six independent 95% checks, at least one would be expected to miss about 26% of the time even if every model followed its published rate exactly. Six out of six is a reassuring outcome, not a tightly controlled family-wide claim.
  • A gateway is not a serving snapshot. Requests pinned the named first-party provider and refused fallbacks, which rules out silent substitution. It cannot prove this run and the published run reached identical model snapshots.

The remaining $0.90 is reported as an attribution gap rather than assigned to this gate without evidence. The append-only ledger holds 1,448 attempts against 1,430 distinct keys. The latest-state table still contains one logical row per model and item, while the prior failures remain auditable.

What happens next

The environment is validated, so the treatment arms run against a control that is known to behave. That experiment, whether announcing a scoring rule changes how often a model declines to answer, has since had its first pass: the 50-item existence check passed on 2026-08-15 and is reported on the findings page. The larger estimation run has not started, and its result will appear there whether or not the hypothesis survives.

Every number on this page is rendered from gpqa_parity.csv and gpqa_parity_summary.csv, which are published beside this page. The pre-registered targets and the pass criterion live in the code that graded the runs, and the builder re-checks the two against each other, so a page that disagreed with its own source would fail to build rather than publish. Neither file contains any benchmark question text.

Targets, sample sizes, and the pass criterion are versioned with the run record. Exclusions remain visible rather than being repaired into a cleaner story.
